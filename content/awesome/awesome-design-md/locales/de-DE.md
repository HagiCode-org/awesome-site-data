# DESIGN.md-Sammlung

Kopieren Sie eine DESIGN.md in Ihr Projekt, sagen Sie Ihrem KI-Agenten "Bauen Sie mir eine Seite, die so aussieht" und generieren Sie eine qualitativ hochwertige Benutzeroberfläche, die visuell konsistent mit der Designsprache bleibt.

Gebaut mit echter Designtiefe - einschließlich analysierter Muster, Token und Regeln - für eine qualitativ hochwertige UI-Generierung, nicht für Ausgaben auf Oberflächenebene.


## Was ist DESIGN.md?

[DESIGN.md](https://stitch.withgoogle.com/docs/design-md/overview/) ist ein neues Konzept, das von Google Stitch eingeführt wurde. Ein Klartext-Design-Systemdokument, das KI-Agenten lesen, um eine konsistente Benutzeroberfläche zu generieren.

Es ist nur eine Markdown-Datei. Keine Figma-Exporte, keine JSON-Schemata, keine speziellen Werkzeuge. Legen Sie es in Ihren Projektstamm und jeder AI-Codierungsagent oder Google Stitch versteht sofort, wie Ihre Benutzeroberfläche aussehen soll. Markdown ist das Format, das LLMs am besten lesen, also gibt es nichts zu analysieren oder zu konfigurieren.

| Datei | Wer liest es | Was es definiert |
|------|-------------|-----------------|
| `AGENTS.md` | Codierungsmittel | Wie man das Projekt baut |
| `DESIGN.md` | Design-Agenten | Wie das Projekt aussehen und sich anfühlen sollte |

**Dieses Repo bietet gebrauchsfertige DESIGN.md-Dateien**von echten Websites extrahiert.

## Ein DESIGN.md anfordern

Sie können[ein DESIGN.md anfordern](https://getdesign.md/request) für bestimmte Websites, einschließlich privater Anfragen, die ausschließlich an Sie gesendet werden.

## Was steckt in jeder DESIGN.md?

Jede Datei folgt dem[Stitch-DESIGN.md-Format](https://stitch.withgoogle.com/docs/design-md/specification/) mit verlängerten Abschnitten:

| # | Abschnitt | Was es einfängt |
|---|---------|-----------------|
| 1 | Visual Theme & Atmosphäre | Stimmung, Dichte, Designphilosophie |
| 2 | Farbpalette und Rollen | Semantische Bezeichnung + hex + funktionelle Rolle |
| 3 | Typografievorschriften | Schriftfamilien, vollständige Hierarchietabelle |
| 4 | Komponentenformgebungen | Tasten, Karten, Eingaben, Navigation mit Zuständen |
| 5 | Layoutprinzipien | Abstand Skala, Gitter, Whitespace Philosophie |
| 6 | Tiefe und Höhe | Schattensystem, Oberflächenhierarchie |
| 7 | Do's und Don'ts | Konstruktionsleitplanken und Anti-Muster |
| 8 | Responsives Verhalten | Breakpoints, Touch-Ziele, Zusammenbruchsstrategie |
| 9 | Agent Prompt Guide | Schnelle Farbreferenz, gebrauchsfertige Aufforderungen |

Jede Website umfasst:

| Datei | Zweck |
|------|---------|
| `DESIGN.md` | Das Designsystem (was Agenten lesen) |
| `preview.html` | Visueller Katalog mit Farbfeldern, Typskala, Schaltflächen, Karten |
| `preview-dark.html` | Der gleiche Katalog mit dunklen Oberflächen |

### Verwendung


1. Kopieren einer Website`DESIGN.md`In Ihre Projektwurzel
2. Sagen Sie Ihrem KI-Agenten, dass er es verwenden soll.


## Mitwirken

Siehe[BEITRAG.md](CONTRIBUTING.md) für Leitlinien.

- **Bestehende Dateien verbessern**Fix falsche Farben, fehlende Token, schwache Beschreibungen
- **Berichtsprobleme**: Lassen Sie uns wissen, ob etwas absieht

Bevor Sie eine PR eröffnen, bitte[Offenes Problem](https://github.com/VoltAgent/awesome-design-md/issues) zuerst Ihre Idee zu diskutieren und Feedback von Maintainern zu erhalten.
