## Workflow

1. `status` — note the covered line count.
2. `report` — for each reported line: translate it and `fix` it. Write the replacement to a temp file such as `content/awesome/awesome-ios/locales/.next-<locale>.md`, run `fix`, then delete the temp file. Notes:
   - HTML structural lines (`<div ...>`, `<p ...>`, `<br>`, `</p>` ...) legitimately stay identical; only translate human-readable attribute text such as `alt="Buy Me a Coffee"`.
   - Do NOT rewrite any other already-translated line.
3. Append loop until status shows 3056/3056:
   1. Chunk range: start = covered + 1, end = min(start + 219, 3056).
   2. Read the exact source lines: `sed -n '<start>,<end>p' sources/awesome-ios/README.md`.
   3. Translate into exactly one output line per source line; write the chunk to `content/awesome/awesome-ios/locales/.next-<locale>.md` (one trailing newline at the end).
   4. `check <locale> <start> content/awesome/awesome-ios/locales/.next-<locale>.md`
   5. On errors, fix the candidate file and re-run `check` (validation failures append nothing). On `WARN` lines, review each: fix real misses; lines with genuinely no translatable prose (name-only entries, pure badges/URLs, HTML structure) may stay identical.
   6. Delete the candidate temp file only after a successful `check`, then continue with the next chunk.
4. `finish <locale>` — it prints `structure OK: ...` and `wrote content/awesome/awesome-ios/locales/<locale>.md`. If it fails, fix the progress file (using `fix`) and re-run.
5. Final report: state the covered line counts and the `finish` output summary.

  - asterisk counts (bold/italic markers) and HTML tag structure.

- Terminology consistency: your seeded prefix already contains the fully translated "Contents" list — it is your glossary. When you translate a section heading, find the matching TOC label in your progress file and reuse the exact same wording. Follow the seed's established style and phrasing conventions.
