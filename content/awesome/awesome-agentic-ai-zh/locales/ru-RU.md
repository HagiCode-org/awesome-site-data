## 🎯 Чем поможет эта карта?

**AI Agent** (ИИ-агент) — это «система ИИ, которая ради цели человека сама решает, какой шаг предпринять дальше, и действует». Получив цель, он оценивает текущую ситуацию, выбирает следующий шаг, при необходимости использует инструменты, а затем в зависимости от результата продолжает, исправляет, останавливается или возвращает управление человеку. Он может автоматически выполнять работу за вас, но только в рамках правил и полномочий, которые вы ему дали. Чат-бот, отвечающий лишь один раз, или скрипт, где каждый шаг заранее жёстко прописан, не обязательно являются агентом. Этот репозиторий не требует, чтобы вы сразу знали все термины, — он проведёт вас последовательно через три задачи:

1. **Сначала понять основы**: что такое LLM (Large Language Model, модель, способная читать и писать текст на языке), Prompt, API (Application Programming Interface, интерфейс, через который программа вызывает сервис) и Token.
2. **Затем создать что-то**: позволить модели вызывать инструменты, запустить Agent Loop, читать документы и запоминать информацию.
3. **Наконец, сделать это надёжным**: добавить права доступа, Eval, ручное подтверждение, наблюдаемость и восстановление после сбоев.

Здесь роль — это **учебный маршрут + отобранные ресурсы + небольшие упражнения, которые можно сразу запустить**. Когда нужна полная глава, мы направим вас к официальной документации, [Datawhale Hello-Agents](https://github.com/datawhalechina/hello-agents) или соответствующему Cookbook, вместо того чтобы переписывать очередную энциклопедию. Когда требуется подключить модель, каждое упражнение отдельно поясняет облачный или локальный путь.

Важные технические термины при первом появлении сначала объясняются простыми словами, а затем сохраняется официальное английское написание. Если забыли какое-то слово, просто загляните в [глоссарий](resources/glossary.md).

Читатели Track A / B сначала проходят **общие основы Stage 0–2**; те, кто уже знает Python, Git и API, могут пропустить Stage 0. Повседневный пользователь может сразу идти по руководству ролей.

Stage 4 сначала понимает **Workflow Graph**, затем реализует его через framework; Stage 7 добавляет Eval, наблюдаемость, подтверждение и восстановление, чтобы одна и та же рабочая карта работала стабильно.

> 🔭 **Порядок обучения**: Stage 2 Prompt → Stage 3 **Agent Loop** → Stage 4 **Workflow Graph** / Framework → Stage 5 инструменты и правила → Stage 6 **Context Engineering** → Stage 7 production. Prompt, Context, Harness, Loop, Graph работают вместе; это не пять слоёв и не сменяющие друг друга поколения продуктов.

После завершения A3 или Stage 7 можно начать [Capstone-проект](CAPSTONE.md); для отслеживания прогресса используйте [PROGRESS.md](PROGRESS.md).

<summary>⏱️ Посмотреть оценку времени (для планирования, не как дедлайн)</summary>

- **Track A**: около 8–10 недель. Акцент на использовании готовых CLI Agent для выполнения работы.

## 💡 Как учиться, чтобы не застрять?

1. **Проходите только один Stage за раз**: сначала ответьте на ключевой вопрос этой главы.
2. **Сначала смотрите ключевые термины и обязательное к чтению**: они напрямую используются в последующих упражнениях.
3. **Сразу скопируйте первую команду**: сначала запустите офлайн-тест, не нужно копировать пустой файл.
4. **Меняйте за раз только одну вещь**: после изменения сразу снова запустите тест, чтобы понять, какое именно изменение повлияло на результат.
5. **Переходите дальше только при выполнении условий завершения**: понять — не значит уметь сделать.

Каждый `starter.py` — это запускаемый пример. Сначала посмотрите условие задачи и критерий успеха, затем измените одно место и снова запустите тест. Полный метод см. в [как использовать этот учебный материал](docs/HOW_TO_USE.md).
