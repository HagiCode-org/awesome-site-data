#### カオスエンジニアリングとは何ですか？
> カオスエンジニアリングとは、分散システムに対して実験を行い、本番環境における乱れた状況に耐えるシステムの能力に対する自信を築くための規律である。 - [Principles Of Chaos Engineering](http://principlesofchaos.org/) ウェブサイト。

## 主なツール
* [Chaos Monkey](https://github.com/Netflix/chaosmonkey) - アプリケーションがランダムなインスタンス障害に耐えられるようにするためのレジリエンスツール。
* [orchestrator](https://github.com/github/orchestrator) - MySQL レプリケーション・トポロジ管理および高可用性。
* [kube-monkey](https://github.com/asobti/kube-monkey) - Kubernetes クラスター向けの Netflix の Chaos Monkey 実装。
* [Gremlin Inc.](https://www.gremlin.com/) - Failure as a Service（障害をサービスとして提供）。
* [Chaos Toolkit](https://github.com/chaostoolkit/chaostoolkit) - ソフトウェアシステムへの自信を築くためのカオスエンジニアリングツールキット。
* [steadybit](https://www.steadybit.com/) - 自動検出機能、さまざまな攻撃タイプ、ユーザー管理などを備えたカオスエンジニアリングプラットフォーム（SaaS またはオンプレミス）。
* [PowerfulSeal](https://github.com/bloomberg/powerfulseal) - Kubernetes クラスターにカオスを加え、システムの問題を可能な限り早期に検出できるようにする。ターゲットの Pod を終了させ、VM の起動と停止を行う。
* [drax](https://github.com/dcos-labs/drax) - DC/OS レジリエンス自動化診断ツール。Chaos Monkey に着想を得た、積極的かつ侵襲的なテストアプローチを適用して DC/OS デプロイメントをテストするのに役立つ。
* [Wiremock](http://wiremock.org/) - 実際の障害や遅延をモデル化できる API モッキング（サービス仮想化）。
* [MockLab](http://get.mocklab.io/) - 実際の障害や遅延をモデル化できる API モッキング（サービス仮想化）をサービスとして提供。
* [Pod-Reaper](https://github.com/target/pod-reaper) - ルールベースの Pod 終了コンテナ。Pod-Reaper は特定の条件を満たす Pod を終了させるように設計されており、Kubernetes でのカオステストに使用できる。
* [Muxy](https://github.com/mefellows/muxy/) - 実際の分散システム障害をシミュレートするためのカオステストツール。
* [Toxiproxy](https://github.com/Shopify/toxiproxy) - カオスおよびレジリエンステストのためのネットワークやシステム条件をシミュレートするための TCP プロキシ。
* Docker 向けカオスエンジニアリング：
  * [Pumba](https://github.com/gaia-adm/pumba) - Docker コンテナ（およびクラスター）向けのカオステストおよびネットワークエミュレーション。
  * [Blockade](https://github.com/worstcase/blockade) - 分散アプリケーションのネットワーク障害やパーティションをテストするための Docker ベースのユーティリティ。
* [chaos-lambda](https://github.com/bbc/chaos-lambda) - 業務時間中に ASG インスタンスをランダムに終了させる。
* [Namazu](https://github.com/osrg/namazu) - 分散システムをテストするためのプログラム可能なファジースケジューラ。
* [Chaos Monkey for Spring Boot](https://codecentric.github.io/chaos-monkey-spring-boot/) - Spring Boot アプリケーションに遅延、例外、終了を注入する。
* [Byte-Monkey](https://github.com/mrwilson/byte-monkey) - JVM 向けのバイトコードレベルの障害注入。アプリケーションコードを実行時に動的にインストルメント化し、例外や遅延などの障害を意図的に導入する。
* [GomJabbar](https://github.com/outbrain/GomJabbar) - プライベートクラウド向けの ChaosMonkey。
* [Turbulence](https://github.com/cppforlife/turbulence-release) - BOSH 環境に特化したツールで、VM に負荷をかけ、ネットワークトラフィックを操作するなどが可能。Gremlin と非常に似ている。
* [chaosblade](https://github.com/chaosblade-io/chaosblade) - 使いやすく強力なカオスエンジニアリングツールキット。
* [KubeInvaders](https://github.com/lucky-sideburn/KubeInvaders) - Kubernetes クラスター向けのゲーム化されたカオスエンジニアリングツール。
* [Cthulhu](https://github.com/xmatters/cthulhu-chaos-testing) - データ駆動の方法でターゲットインフラストラクチャに対してさまざまな災害シナリオをシミュレートし、マイクロサービスシステムのレジリエンスを評価するカオスエンジニアリングツール。
* [VMware Mangle](https://vmware.github.io/mangle/) - カオスエンジニアリングのオーケストレーション。
* [Byteman](https://byteman.jboss.org/) - バイトコード操作のためのスイスアーミーナイフ。
* [Litmus](https://github.com/litmuschaos/litmus) - Kubernetes 環境向けのフレームワーク。テストスイートの実行、ログの取得、レポートの生成、カオステストの実行ができる。
* [Perses](https://github.com/nicolasmanic/perses) - JVM アプリケーションに（制御された）破壊を引き起こすプロジェクト。
* [ChaosKube](https://github.com/linki/chaoskube) - chaoskube は Kubernetes クラスター内のランダムな Pod を定期的に終了させる。
* [Chaos Mesh](https://github.com/chaos-mesh/chaos-mesh) - Chaos Mesh は、Kubernetes 環境でカオスをオーケストレーションするクラウドネイティブなカオスエンジニアリングプラットフォーム。
* [failure-lambda](https://github.com/gunnargrosch/failure-lambda) - 遅延、例外、ステータスコード、ディスク容量を用いて AWS Lambda に障害を注入するための小さな Node モジュール。
* [aws-chaos-scripts](https://github.com/adhorn/aws-chaos-scripts) - AWS インフラストラクチャで障害注入を実行するための Python スクリプトのコレクション。
* [chaos-ssm-documents](https://github.com/adhorn/chaos-ssm-documents) - カオスエンジニアリング実験を実行するための AWS SSM ドキュメントのコレクション。
* [aws-lambda-chaos-injection](https://github.com/adhorn/aws-lambda-chaos-injection) - AWS Lambda にカオスを注入するライブラリ。遅延、例外、statusCode の注入を行うシンプルな Python デコレータと、任意のサードパーティ依存関係に遅延を追加するクラスを提供する。
* [chaos-dingo](https://github.com/jmspring/chaos-dingo) - Azure NodeJS SDK を使用して Azure サービスをかき回すツール。
* [Chaos HTTP Proxy](https://github.com/bouncestorage/chaos-http-proxy) - プロキシサーバーを介して HTTP リクエストに障害を導入する。
* [Chaos Lemur](https://github.com/strepsirrhini-army/chaos-lemur) - BOSH 管理環境で仮想マシンをランダムに破壊するための自己ホスト型アプリケーション。
* [Simoorg](https://github.com/linkedin/simoorg) - LinkedIn 独自の障害誘発フレームワーク。
* [react-chaos](https://github.com/jchiatt/react-chaos) - React アプリ向けのカオスエンジニアリングツール。
* [vue-chaos](https://github.com/aviadhahami/vue-chaos) - Vue アプリ向けのカオスエンジニアリングツール。
* [Chaos Engine](https://github.com/ThalesGroup/chaos-engine) - クラウドベースのインフラストラクチャで実行されているアプリケーションリソースを断続的に破壊または劣化させるように設計されたツール。[Documentation](https://thalesgroup.github.io/chaos-engine/)
