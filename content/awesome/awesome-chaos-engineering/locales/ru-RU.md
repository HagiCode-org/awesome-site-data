Подборка отличных ресурсов по [Chaos Engineering](http://principlesofchaos.org/) (инженерии хаоса).

#### Что такое инженерия хаоса?
> Инженерия хаоса — это дисциплина проведения экспериментов на распределённой системе для построения уверенности в способности системы выдерживать турбулентные условия в производственной среде. — Сайт [Principles Of Chaos Engineering](http://principlesofchaos.org/).

## Примечательные инструменты
* [Chaos Monkey](https://github.com/Netflix/chaosmonkey) - Инструмент отказоустойчивости, помогающий приложениям выдерживать случайные сбои экземпляров.
* [orchestrator](https://github.com/github/orchestrator) - Управление топологией репликации MySQL и высокая доступность.
* [kube-monkey](https://github.com/asobti/kube-monkey) - Реализация Chaos Monkey от Netflix для кластеров Kubernetes.
* [Gremlin Inc.](https://www.gremlin.com/) - Failure as a Service (сбой как услуга).
* [Chaos Toolkit](https://github.com/chaostoolkit/chaostoolkit) - Набор инструментов инженерии хаоса, помогающий обрести уверенность в вашей программной системе.
* [steadybit](https://www.steadybit.com/) - Платформа инженерии хаоса (SaaS или On-Prem) с автообнаружением, различными типами атак, управлением пользователями и многим другим.
* [PowerfulSeal](https://github.com/bloomberg/powerfulseal) - Добавляет хаос в ваши кластеры Kubernetes, чтобы вы могли как можно раньше обнаруживать проблемы в системах. Он завершает целевые поды и поднимает и опускает ВМ.
* [drax](https://github.com/dcos-labs/drax) - Инструмент автоматизированной диагностики устойчивости DC/OS. Он помогает тестировать развёртывания DC/OS, применяя проактивный и инвазивный подход к тестированию, вдохновлённый Chaos Monkey.
* [Wiremock](http://wiremock.org/) - Мокирование API (виртуализация сервисов), позволяющая моделировать реальные сбои и задержки.
* [MockLab](http://get.mocklab.io/) - Мокирование API (виртуализация сервисов) как услуга, позволяющая моделировать реальные сбои и задержки.
* [Pod-Reaper](https://github.com/target/pod-reaper) - Контейнер на основе правил для завершения подов. Pod-Reaper был создан для завершения подов, отвечающих определённым условиям, и может использоваться для тестирования хаоса в Kubernetes.
* [Muxy](https://github.com/mefellows/muxy/) - Инструмент тестирования хаоса для моделирования сбоев реальных распределённых систем.
* [Toxiproxy](https://github.com/Shopify/toxiproxy) - TCP-прокси для моделирования сетевых и системных условий для тестов хаоса и устойчивости.
* Инженерия хаоса для Docker:
  * [Pumba](https://github.com/gaia-adm/pumba) - Тестирование хаоса и эмуляция сети для контейнеров (и кластеров) Docker.
  * [Blockade](https://github.com/worstcase/blockade) - Утилита на базе Docker для тестирования сетевых сбоев и разделений в распределённых приложениях.
* [chaos-lambda](https://github.com/bbc/chaos-lambda) - Случайно завершает экземпляры ASG в рабочее время.
* [Namazu](https://github.com/osrg/namazu) - Программируемый нечёткий планировщик для тестирования распределённых систем.
* [Chaos Monkey for Spring Boot](https://codecentric.github.io/chaos-monkey-spring-boot/) - Внедряет задержки, исключения и завершения в приложения Spring Boot.
* [Byte-Monkey](https://github.com/mrwilson/byte-monkey) - Внедрение сбоев на уровне байт-кода для JVM. Он инструментирует код приложения на лету, намеренно вызывая сбои вроде исключений и задержек.
* [GomJabbar](https://github.com/outbrain/GomJabbar) - ChaosMonkey для вашего частного облака.
* [Turbulence](https://github.com/cppforlife/turbulence-release) - Инструмент, ориентированный на среды BOSH, способный нагружать ВМ, манипулировать сетевым трафиком и многое другое. Очень похож на Gremlin.
* [chaosblade](https://github.com/chaosblade-io/chaosblade) - Простой в использовании и мощный набор инструментов инженерии хаоса.
* [KubeInvaders](https://github.com/lucky-sideburn/KubeInvaders) - Геймифицированный инструмент инженерии хаоса для кластеров Kubernetes.
* [Cthulhu](https://github.com/xmatters/cthulhu-chaos-testing) - Инструмент инженерии хаоса, помогающий оценивать устойчивость систем микросервисов, моделируя различные сценарии катастроф на целевой инфраструктуре на основе данных.
* [VMware Mangle](https://vmware.github.io/mangle/) - Оркестрация инженерии хаоса.
* [Byteman](https://byteman.jboss.org/) - Швейцарский нож для манипуляций с байт-кодом.
* [Litmus](https://github.com/litmuschaos/litmus) - Фреймворк для сред Kubernetes, позволяющий пользователям запускать наборы тестов, собирать логи, генерировать отчёты и проводить тесты хаоса.
* [Perses](https://github.com/nicolasmanic/perses) - Проект для нанесения (контролируемого) ущерба приложению JVM.
* [ChaosKube](https://github.com/linki/chaoskube) - chaoskube периодически завершает случайные поды в вашем кластере Kubernetes.
* [Chaos Mesh](https://github.com/chaos-mesh/chaos-mesh) - Chaos Mesh — это облачная нативная платформа инженерии хаоса, которая оркестрирует хаос в средах Kubernetes.
* [failure-lambda](https://github.com/gunnargrosch/failure-lambda) - Небольшой модуль Node для внедрения сбоев в AWS Lambda с помощью задержки, исключения, кода состояния или дискового пространства.
* [aws-chaos-scripts](https://github.com/adhorn/aws-chaos-scripts) - Набор Python-скриптов для выполнения внедрения сбоев в инфраструктуре AWS.
* [chaos-ssm-documents](https://github.com/adhorn/chaos-ssm-documents) - Набор документов AWS SSM для проведения экспериментов по инженерии хаоса.
* [aws-lambda-chaos-injection](https://github.com/adhorn/aws-lambda-chaos-injection) - Библиотека, внедряющая хаос в AWS Lambda. Она предоставляет простые Python-декораторы для внедрения задержки, исключения и statusCode, а также класс для добавления задержки любым сторонним зависимостям.
* [chaos-dingo](https://github.com/jmspring/chaos-dingo) - Инструмент для вмешательства в сервисы Azure с помощью Azure NodeJS SDK.
* [Chaos HTTP Proxy](https://github.com/bouncestorage/chaos-http-proxy) - Внедряет сбои в HTTP-запросы через прокси-сервер.
* [Chaos Lemur](https://github.com/strepsirrhini-army/chaos-lemur) - Самостоятельно размещаемое приложение для случайного уничтожения виртуальных машин в среде под управлением BOSH.
* [Simoorg](https://github.com/linkedin/simoorg) - Собственный фреймворк индукции сбоев от LinkedIn.
