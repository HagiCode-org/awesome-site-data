Une liste curée de ressources [Chaos Engineering](http://principlesofchaos.org/) (ingénierie du chaos).

#### Qu'est-ce que l'ingénierie du chaos ?
> L'ingénierie du chaos est la discipline qui consiste à expérimenter sur un système distribué afin de renforcer la confiance dans la capacité du système à résister à des conditions perturbées en production. — Site web des [Principles Of Chaos Engineering](http://principlesofchaos.org/).

## Outils notables
* [Chaos Monkey](https://github.com/Netflix/chaosmonkey) - Un outil de résilience qui aide les applications à tolérer des pannes d'instances aléatoires.
* [orchestrator](https://github.com/github/orchestrator) - Gestion de la topologie de réplication MySQL et haute disponibilité.
* [kube-monkey](https://github.com/asobti/kube-monkey) - Une implémentation du Chaos Monkey de Netflix pour les clusters Kubernetes.
* [Gremlin Inc.](https://www.gremlin.com/) - Failure as a Service (la panne en tant que service).
* [Chaos Toolkit](https://github.com/chaostoolkit/chaostoolkit) - Une boîte à outils d'ingénierie du chaos pour vous aider à avoir confiance en votre système logiciel.
* [steadybit](https://www.steadybit.com/) - Une plateforme d'ingénierie du chaos (SaaS ou sur site) avec découverte automatique, différents types d'attaques, gestion des utilisateurs et bien plus.
* [PowerfulSeal](https://github.com/bloomberg/powerfulseal) - Ajoute du chaos à vos clusters Kubernetes afin de détecter les problèmes dans vos systèmes le plus tôt possible. Il tue les pods ciblés et fait monter et descendre les machines virtuelles.
* [drax](https://github.com/dcos-labs/drax) - Outil de diagnostic automatisé de résilience DC/OS. Il aide à tester les déploiements DC/OS en appliquant une approche de test proactive et invasive inspirée de Chaos Monkey.
* [Wiremock](http://wiremock.org/) - Simulation d'API (virtualisation de services) permettant de modéliser des pannes et des latences réelles.
* [MockLab](http://get.mocklab.io/) - Simulation d'API (virtualisation de services) en tant que service, permettant de modéliser des pannes et des latences réelles.
* [Pod-Reaper](https://github.com/target/pod-reaper) - Un conteneur de destruction de pods basé sur des règles. Pod-Reaper a été conçu pour tuer les pods répondant à des conditions spécifiques, utilisable pour les tests de chaos dans Kubernetes.
* [Muxy](https://github.com/mefellows/muxy/) - Un outil de test de chaos pour simuler des pannes de systèmes distribués réels.
* [Toxiproxy](https://github.com/Shopify/toxiproxy) - Un proxy TCP pour simuler des conditions réseau et système lors de tests de chaos et de résilience.
* Ingénierie du chaos pour Docker :
  * [Pumba](https://github.com/gaia-adm/pumba) - Test de chaos et émulation réseau pour les conteneurs (et clusters) Docker.
  * [Blockade](https://github.com/worstcase/blockade) - Utilitaire basé sur Docker pour tester les pannes réseau et les partitions dans les applications distribuées.
* [chaos-lambda](https://github.com/bbc/chaos-lambda) - Termine aléatoirement des instances ASG pendant les heures ouvrables.
* [Namazu](https://github.com/osrg/namazu) - Planificateur flou programmable pour tester les systèmes distribués.
* [Chaos Monkey for Spring Boot](https://codecentric.github.io/chaos-monkey-spring-boot/) - Injecte des latences, des exceptions et des terminaisons dans les applications Spring Boot.
* [Byte-Monkey](https://github.com/mrwilson/byte-monkey) - Injection de défauts au niveau du bytecode pour la JVM. Il instrumente le code applicatif à la volée pour introduire délibérément des pannes comme des exceptions et des latences.
* [GomJabbar](https://github.com/outbrain/GomJabbar) - ChaosMonkey pour votre cloud privé.
* [Turbulence](https://github.com/cppforlife/turbulence-release) - Outil axé sur les environnements BOSH, capable de stresser les machines virtuelles, de manipuler le trafic réseau, etc. Il est très similaire à Gremlin.
* [chaosblade](https://github.com/chaosblade-io/chaosblade) - Une boîte à outils d'ingénierie du chaos facile à utiliser et puissante.
* [KubeInvaders](https://github.com/lucky-sideburn/KubeInvaders) - Outil d'ingénierie du chaos gamifié pour les clusters Kubernetes.
* [Cthulhu](https://github.com/xmatters/cthulhu-chaos-testing) - Outil d'ingénierie du chaos qui aide à évaluer la résilience des systèmes de microservices en simulant divers scénarios de catastrophe sur une infrastructure cible de manière pilotée par les données.
* [VMware Mangle](https://vmware.github.io/mangle/) - Orchestration de l'ingénierie du chaos.
* [Byteman](https://byteman.jboss.org/) - Un couteau suisse pour la manipulation de bytecode.
* [Litmus](https://github.com/litmuschaos/litmus) - Un framework pour les environnements Kubernetes permettant d'exécuter des suites de tests, de capturer des journaux, de générer des rapports et d'effectuer des tests de chaos.
* [Perses](https://github.com/nicolasmanic/perses) - Un projet visant à provoquer une destruction (contrôlée) d'une application JVM.
* [ChaosKube](https://github.com/linki/chaoskube) - chaoskube tue périodiquement des pods aléatoires dans votre cluster Kubernetes.
* [Chaos Mesh](https://github.com/chaos-mesh/chaos-mesh) - Chaos Mesh est une plateforme d'ingénierie du chaos cloud native qui orchestre le chaos dans les environnements Kubernetes.
* [failure-lambda](https://github.com/gunnargrosch/failure-lambda) - Un petit module Node pour injecter des pannes dans AWS Lambda via latence, exception, code d'état ou espace disque.
* [aws-chaos-scripts](https://github.com/adhorn/aws-chaos-scripts) - Collection de scripts Python pour exécuter l'injection de pannes sur l'infrastructure AWS.
* [chaos-ssm-documents](https://github.com/adhorn/chaos-ssm-documents) - Collection de documents AWS SSM pour réaliser des expériences d'ingénierie du chaos.
* [aws-lambda-chaos-injection](https://github.com/adhorn/aws-lambda-chaos-injection) - Une bibliothèque injectant du chaos dans AWS Lambda. Elle offre de simples décorateurs Python pour l'injection de latence, d'exception et de code d'état, ainsi qu'une classe pour ajouter de la latence à toute dépendance tierce.
* [chaos-dingo](https://github.com/jmspring/chaos-dingo) - Un outil pour perturber les services Azure à l'aide du SDK Azure NodeJS.
* [Chaos HTTP Proxy](https://github.com/bouncestorage/chaos-http-proxy) - Introduit des pannes dans les requêtes HTTP via un serveur proxy.
* [Chaos Lemur](https://github.com/strepsirrhini-army/chaos-lemur) - Une application auto-hébergeable pour détruire aléatoirement des machines virtuelles dans un environnement géré par BOSH.
* [Simoorg](https://github.com/linkedin/simoorg) - Le framework d'induction de pannes bien à LinkedIn.
* [react-chaos](https://github.com/jchiatt/react-chaos) - Un outil d'ingénierie du chaos pour vos applications React.
