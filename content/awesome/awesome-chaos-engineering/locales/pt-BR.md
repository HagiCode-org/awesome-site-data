Uma lista selecionada de recursos incríveis sobre [Chaos Engineering](http://principlesofchaos.org/) (engenharia do caos).

#### O que é Engenharia do Caos?
> Engenharia do Caos é a disciplina de realizar experimentos em um sistema distribuído para construir confiança na capacidade do sistema de resistir a condições turbulentas em produção. - Site dos [Principles Of Chaos Engineering](http://principlesofchaos.org/).

## Ferramentas notáveis
* [Chaos Monkey](https://github.com/Netflix/chaosmonkey) - Uma ferramenta de resiliência que ajuda as aplicações a tolerar falhas de instância aleatórias.
* [orchestrator](https://github.com/github/orchestrator) - Gerenciamento de topologia de replicação MySQL e alta disponibilidade.
* [kube-monkey](https://github.com/asobti/kube-monkey) - Uma implementação do Chaos Monkey da Netflix para clusters Kubernetes.
* [Gremlin Inc.](https://www.gremlin.com/) - Failure as a Service (falha como serviço).
* [Chaos Toolkit](https://github.com/chaostoolkit/chaostoolkit) - Um kit de ferramentas de engenharia do caos para ajudá-lo a construir confiança no seu sistema de software.
* [steadybit](https://www.steadybit.com/) - Uma plataforma de engenharia do caos (SaaS ou on-premise) com recursos de autodescoberta, diferentes tipos de ataque, gerenciamento de usuários e muito mais.
* [PowerfulSeal](https://github.com/bloomberg/powerfulseal) - Adiciona caos aos seus clusters Kubernetes, para que você possa detectar problemas em seus sistemas o mais cedo possível. Ele mata pods direcionados e sobe e desce VMs.
* [drax](https://github.com/dcos-labs/drax) - Ferramenta de Diagnóstico Automatizado de Resiliência DC/OS. Ela ajuda a testar implantações DC/OS aplicando uma abordagem de teste proativa e invasiva inspirada no Chaos Monkey.
* [Wiremock](http://wiremock.org/) - Mock de API (virtualização de serviços) que permite modelar falhas e atrasos do mundo real.
* [MockLab](http://get.mocklab.io/) - Mock de API (virtualização de serviços) como um serviço que permite modelar falhas e atrasos do mundo real.
* [Pod-Reaper](https://github.com/target/pod-reaper) - Um contêiner baseado em regras para matar pods. O Pod-Reaper foi projetado para matar pods que atendem a condições específicas e pode ser usado para testes de caos no Kubernetes.
* [Muxy](https://github.com/mefellows/muxy/) - Uma ferramenta de teste de caos para simular falhas de sistemas distribuídos reais.
* [Toxiproxy](https://github.com/Shopify/toxiproxy) - Um proxy TCP para simular condições de rede e sistema para testes de caos e resiliência.
* Engenharia do caos para Docker:
  * [Pumba](https://github.com/gaia-adm/pumba) - Teste de caos e emulação de rede para contêineres (e clusters) Docker.
  * [Blockade](https://github.com/worstcase/blockade) - Utilitário baseado em Docker para testar falhas de rede e partições em aplicações distribuídas.
* [chaos-lambda](https://github.com/bbc/chaos-lambda) - Encerra instâncias ASG aleatoriamente durante o horário comercial.
* [Namazu](https://github.com/osrg/namazu) - Agendador aproximado programável para testar sistemas distribuídos.
* [Chaos Monkey for Spring Boot](https://codecentric.github.io/chaos-monkey-spring-boot/) - Injeta latências, exceções e terminações em aplicações Spring Boot.
* [Byte-Monkey](https://github.com/mrwilson/byte-monkey) - Injeção de falhas em nível de bytecode para a JVM. Ele instrumenta o código da aplicação em tempo de execução para introduzir deliberadamente falhas como exceções e latência.
* [GomJabbar](https://github.com/outbrain/GomJabbar) - ChaosMonkey para sua nuvem privada.
* [Turbulence](https://github.com/cppforlife/turbulence-release) - Ferramenta focada em ambientes BOSH, capaz de estressar VMs, manipular tráfego de rede e mais. É muito similar ao Gremlin.
* [chaosblade](https://github.com/chaosblade-io/chaosblade) - Um kit de ferramentas de engenharia do caos fácil de usar e poderoso.
* [KubeInvaders](https://github.com/lucky-sideburn/KubeInvaders) - Ferramenta de engenharia do caos gamificada para clusters Kubernetes.
* [Cthulhu](https://github.com/xmatters/cthulhu-chaos-testing) - Ferramenta de engenharia do caos que ajuda a avaliar a resiliência de sistemas de microsserviços simulando vários cenários de desastre contra uma infraestrutura-alvo de maneira orientada por dados.
* [VMware Mangle](https://vmware.github.io/mangle/) - Orquestração de engenharia do caos.
* [Byteman](https://byteman.jboss.org/) - Um canivete suíço para manipulação de bytecode.
* [Litmus](https://github.com/litmuschaos/litmus) - Framework para ambientes Kubernetes que permite aos usuários executar suítes de teste, capturar logs, gerar relatórios e realizar testes de caos.
* [Perses](https://github.com/nicolasmanic/perses) - Um projeto para causar destruição (controlada) a uma aplicação JVM.
* [ChaosKube](https://github.com/linki/chaoskube) - o chaoskube mata periodicamente pods aleatórios no seu cluster Kubernetes.
* [Chaos Mesh](https://github.com/chaos-mesh/chaos-mesh) - O Chaos Mesh é uma plataforma de engenharia do caos nativa da nuvem que orquestra o caos em ambientes Kubernetes.
* [failure-lambda](https://github.com/gunnargrosch/failure-lambda) - Um pequeno módulo Node para injetar falhas no AWS Lambda usando latência, exceção, código de status ou espaço em disco.
* [aws-chaos-scripts](https://github.com/adhorn/aws-chaos-scripts) - Coleção de scripts Python para executar injeção de falhas na infraestrutura AWS.
* [chaos-ssm-documents](https://github.com/adhorn/chaos-ssm-documents) - Coleção de documentos AWS SSM para realizar experimentos de engenharia do caos.
* [aws-lambda-chaos-injection](https://github.com/adhorn/aws-lambda-chaos-injection) - Uma biblioteca que injeta caos no AWS Lambda. Ela oferece decoradores simples de Python para injeção de latência, exceção e statusCode, e uma classe para adicionar latência a qualquer dependência de terceiros.
* [chaos-dingo](https://github.com/jmspring/chaos-dingo) - Uma ferramenta para mexer com serviços do Azure usando o Azure NodeJS SDK.
* [Chaos HTTP Proxy](https://github.com/bouncestorage/chaos-http-proxy) - Introduz falhas em requisições HTTP por meio de um servidor proxy.
* [Chaos Lemur](https://github.com/strepsirrhini-army/chaos-lemur) - Uma aplicação auto-hospedável para destruir aleatoriamente máquinas virtuais em um ambiente gerenciado por BOSH.
* [Simoorg](https://github.com/linkedin/simoorg) - O próprio framework indutor de falhas da LinkedIn.
* [react-chaos](https://github.com/jchiatt/react-chaos) - Uma ferramenta de engenharia do caos para suas aplicações React.
