Una lista curada de recursos impresionantes sobre [Chaos Engineering](http://principlesofchaos.org/) (ingeniería del caos).

#### ¿Qué es la Ingeniería del Caos?
> La ingeniería del caos es la disciplina de experimentar en un sistema distribuido para construir confianza en la capacidad del sistema para resistir condiciones turbulentas en producción. - Sitio web de [Principles Of Chaos Engineering](http://principlesofchaos.org/).

## Herramientas destacadas
* [Chaos Monkey](https://github.com/Netflix/chaosmonkey) - Una herramienta de resiliencia que ayuda a las aplicaciones a tolerar fallos de instancia aleatorios.
* [orchestrator](https://github.com/github/orchestrator) - Gestión de topología de replicación MySQL y alta disponibilidad.
* [kube-monkey](https://github.com/asobti/kube-monkey) - Una implementación de Chaos Monkey de Netflix para clústeres de Kubernetes.
* [Gremlin Inc.](https://www.gremlin.com/) - Failure as a Service (fallo como servicio).
* [Chaos Toolkit](https://github.com/chaostoolkit/chaostoolkit) - Un kit de herramientas de ingeniería del caos para ayudarte a construir confianza en tu sistema software.
* [steadybit](https://www.steadybit.com/) - Una plataforma de ingeniería del caos (SaaS o local) con funciones de auto-descubrimiento, diferentes tipos de ataques, gestión de usuarios y mucho más.
* [PowerfulSeal](https://github.com/bloomberg/powerfulseal) - Añade caos a tus clústeres de Kubernetes para que puedas detectar problemas en tus sistemas lo antes posible. Mata pods objetivo y sube y baja VMs.
* [drax](https://github.com/dcos-labs/drax) - Herramienta de diagnóstico automatizado de resiliencia DC/OS. Ayuda a probar despliegues DC/OS aplicando un enfoque de pruebas proactivo e invasivo inspirado en Chaos Monkey.
* [Wiremock](http://wiremock.org/) - Simulación de API (virtualización de servicios) que permite modelar fallos y retrasos del mundo real.
* [MockLab](http://get.mocklab.io/) - Simulación de API (virtualización de servicios) como servicio que permite modelar fallos y retrasos del mundo real.
* [Pod-Reaper](https://github.com/target/pod-reaper) - Un contenedor de terminación de pods basado en reglas. Pod-Reaper fue diseñado para matar pods que cumplan condiciones específicas y se puede usar para pruebas de caos en Kubernetes.
* [Muxy](https://github.com/mefellows/muxy/) - Una herramienta de pruebas de caos para simular fallos de sistemas distribuidos reales.
* [Toxiproxy](https://github.com/Shopify/toxiproxy) - Un proxy TCP para simular condiciones de red y sistema para pruebas de caos y resiliencia.
* Ingeniería del caos para Docker:
  * [Pumba](https://github.com/gaia-adm/pumba) - Pruebas de caos y emulación de red para contenedores (y clústeres) Docker.
  * [Blockade](https://github.com/worstcase/blockade) - Utilidad basada en Docker para probar fallos de red y particiones en aplicaciones distribuidas.
* [chaos-lambda](https://github.com/bbc/chaos-lambda) - Termina instancias ASG de forma aleatoria durante el horario laboral.
* [Namazu](https://github.com/osrg/namazu) - Programador difuso programable para probar sistemas distribuidos.
* [Chaos Monkey for Spring Boot](https://codecentric.github.io/chaos-monkey-spring-boot/) - Inyecta latencias, excepciones y terminaciones en aplicaciones Spring Boot.
* [Byte-Monkey](https://github.com/mrwilson/byte-monkey) - Inyección de fallos a nivel de bytecode para la JVM. Funciona instrumentando el código de la aplicación sobre la marcha para introducir deliberadamente fallos como excepciones y latencia.
* [GomJabbar](https://github.com/outbrain/GomJabbar) - ChaosMonkey para tu nube privada.
* [Turbulence](https://github.com/cppforlife/turbulence-release) - Herramienta centrada en entornos BOSH capaz de estresar VMs, manipular el tráfico de red y más. Es muy similar a Gremlin.
* [chaosblade](https://github.com/chaosblade-io/chaosblade) - Un kit de herramientas de ingeniería del caos fácil de usar y potente.
* [KubeInvaders](https://github.com/lucky-sideburn/KubeInvaders) - Herramienta de ingeniería del caos gamificada para clústeres de Kubernetes.
* [Cthulhu](https://github.com/xmatters/cthulhu-chaos-testing) - Herramienta de ingeniería del caos que ayuda a evaluar la resiliencia de los sistemas de microservicios simulando diversos escenarios de desastre contra una infraestructura objetivo de forma basada en datos.
* [VMware Mangle](https://vmware.github.io/mangle/) - Orquestación de la ingeniería del caos.
* [Byteman](https://byteman.jboss.org/) - Un navaja suiza para la manipulación de bytecode.
* [Litmus](https://github.com/litmuschaos/litmus) - Marco para entornos Kubernetes que permite a los usuarios ejecutar suites de pruebas, capturar registros, generar informes y realizar pruebas de caos.
* [Perses](https://github.com/nicolasmanic/perses) - Un proyecto para causar destrucción (controlada) a una aplicación JVM.
* [ChaosKube](https://github.com/linki/chaoskube) - chaoskube mata periódicamente pods aleatorios en tu clúster de Kubernetes.
* [Chaos Mesh](https://github.com/chaos-mesh/chaos-mesh) - Chaos Mesh es una plataforma de ingeniería del caos nativa de la nube que orquesta el caos en entornos Kubernetes.
* [failure-lambda](https://github.com/gunnargrosch/failure-lambda) - Un pequeño módulo Node para inyectar fallos en AWS Lambda usando latencia, excepción, código de estado o espacio en disco.
* [aws-chaos-scripts](https://github.com/adhorn/aws-chaos-scripts) - Colección de scripts de Python para ejecutar inyección de fallos en infraestructura de AWS.
* [chaos-ssm-documents](https://github.com/adhorn/chaos-ssm-documents) - Colección de documentos AWS SSM para realizar experimentos de ingeniería del caos.
* [aws-lambda-chaos-injection](https://github.com/adhorn/aws-lambda-chaos-injection) - Una biblioteca que inyecta caos en AWS Lambda. Ofrece decoradores simples de Python para inyectar latencia, excepción y statusCode, y una clase para añadir latencia a cualquier dependencia de terceros.
* [chaos-dingo](https://github.com/jmspring/chaos-dingo) - Una herramienta para fastidiar servicios de Azure usando el SDK de Azure NodeJS.
* [Chaos HTTP Proxy](https://github.com/bouncestorage/chaos-http-proxy) - Introduce fallos en las solicitudes HTTP a través de un servidor proxy.
* [Chaos Lemur](https://github.com/strepsirrhini-army/chaos-lemur) - Una aplicación auto-alojable para destruir máquinas virtuales de forma aleatoria en un entorno gestionado por BOSH.
* [Simoorg](https://github.com/linkedin/simoorg) - El propio framework de inducción de fallos de LinkedIn.
* [react-chaos](https://github.com/jchiatt/react-chaos) - Una herramienta de ingeniería del caos para tus aplicaciones React.
* [vue-chaos](https://github.com/aviadhahami/vue-chaos) - Una herramienta de ingeniería del caos para tus aplicaciones Vue.
* [Chaos Engine](https://github.com/ThalesGroup/chaos-engine) - herramienta diseñada para destruir o degradar intermitentemente recursos de aplicaciones que se ejecutan en infraestructura basada en la nube. [Documentation](https://thalesgroup.github.io/chaos-engine/)
* [kubedoom](https://github.com/storax/kubedoom) - Mata pods de Kubernetes jugando al DOOM de id Software.
* [kubethanos](https://github.com/berkay-dincer/kubethanos) - Mata la mitad de tus pods de Kubernetes seleccionados aleatoriamente.
* [go-fault](https://github.com/github/go-fault) - Middleware de inyección de fallos en Go.

* [kube-burner](https://github.com/cloud-bulldozer/kube-burner) - Una herramienta destinada a estresar clústeres de Kubernetes creando o eliminando una gran cantidad de objetos.
