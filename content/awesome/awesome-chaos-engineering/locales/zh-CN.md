#### 什么是混沌工程？
> 混沌工程是在分布式系统上进行实验的学科，目的是建立对系统在生产环境中承受动荡条件能力的信心。——[混沌工程原则](http://principlesofchaos.org/)网站。

## 知名工具
* [Chaos Monkey](https://github.com/Netflix/chaosmonkey) - 一款弹性工具，可帮助应用程序容忍随机的实例故障。
* [orchestrator](https://github.com/github/orchestrator) - MySQL 复制拓扑管理与高可用工具。
* [kube-monkey](https://github.com/asobti/kube-monkey) - 面向 Kubernetes 集群的 Netflix Chaos Monkey 实现。
* [Gremlin Inc.](https://www.gremlin.com/) - 故障即服务（Failure as a Service）。
* [Chaos Toolkit](https://github.com/chaostoolkit/chaostoolkit) - 一款混沌工程工具包，帮助你建立对软件系统的信心。
* [steadybit](https://www.steadybit.com/) - 一款混沌工程平台（SaaS 或本地部署），具备自动发现、多种攻击类型、用户管理等功能。
* [PowerfulSeal](https://github.com/bloomberg/powerfulseal) - 为你的 Kubernetes 集群注入混沌，以便尽早发现系统中的问题。它会终止目标 Pod，并使虚拟机上下线。
* [drax](https://github.com/dcos-labs/drax) - DC/OS 弹性自动化诊断工具。它借鉴 Chaos Monkey 的思路，通过主动、侵入式的测试方法来检验 DC/OS 部署。
* [Wiremock](http://wiremock.org/) - API 模拟（服务虚拟化）工具，可对真实世界中的故障和延迟进行建模。
* [MockLab](http://get.mocklab.io/) - 以服务形式提供的 API 模拟（服务虚拟化）工具，可对真实世界中的故障和延迟进行建模。
* [Pod-Reaper](https://github.com/target/pod-reaper) - 一款基于规则的 Pod 终止容器。Pod-Reaper 旨在终止满足特定条件的 Pod，可用于 Kubernetes 中的混沌测试。
* [Muxy](https://github.com/mefellows/muxy/) - 一款用于模拟真实分布式系统故障的混沌测试工具。
* [Toxiproxy](https://github.com/Shopify/toxiproxy) - 一款用于模拟网络与系统条件以进行混沌和弹性测试的 TCP 代理。
* 面向 Docker 的混沌工程：
  * [Pumba](https://github.com/gaia-adm/pumba) - 面向 Docker 容器（及集群）的混沌测试与网络仿真工具。
  * [Blockade](https://github.com/worstcase/blockade) - 基于 Docker 的工具，用于测试分布式应用中的网络故障与分区。
* [chaos-lambda](https://github.com/bbc/chaos-lambda) - 在工作时间随机终止 ASG 实例。
* [Namazu](https://github.com/osrg/namazu) - 用于测试分布式系统的可编程模糊调度器。
* [Chaos Monkey for Spring Boot](https://codecentric.github.io/chaos-monkey-spring-boot/) - 向 Spring Boot 应用中注入延迟、异常和终止。
* [Byte-Monkey](https://github.com/mrwilson/byte-monkey) - 面向 JVM 的字节码级故障注入工具。它通过运行时动态插桩应用代码，故意引入异常和延迟等故障。
* [GomJabbar](https://github.com/outbrain/GomJabbar) - 面向私有云的 ChaosMonkey。
* [Turbulence](https://github.com/cppforlife/turbulence-release) - 专注于 BOSH 环境的工具，能够给虚拟机施加压力、操纵网络流量等。它与 Gremlin 非常相似。
* [chaosblade](https://github.com/chaosblade-io/chaosblade) - 一款易用且强大的混沌工程工具包。
* [KubeInvaders](https://github.com/lucky-sideburn/KubeInvaders) - 面向 Kubernetes 集群的游戏化混沌工程工具。
* [Cthulhu](https://github.com/xmatters/cthulhu-chaos-testing) - 一款混沌工程工具，可通过数据驱动的方式模拟各种灾难场景，评估微服务系统的弹性。
* [VMware Mangle](https://vmware.github.io/mangle/) - 编排混沌工程。
* [Byteman](https://byteman.jboss.org/) - 一款字节码操作的瑞士军刀。
* [Litmus](https://github.com/litmuschaos/litmus) - 面向 Kubernetes 环境的框架，可运行测试套件、捕获日志、生成报告并执行混沌测试。
* [Perses](https://github.com/nicolasmanic/perses) - 一个用于对 JVM 应用造成（可控）破坏的项目。
* [ChaosKube](https://github.com/linki/chaoskube) - chaoskube 会定期随机终止 Kubernetes 集群中的 Pod。
* [Chaos Mesh](https://github.com/chaos-mesh/chaos-mesh) - Chaos Mesh 是一个云原生混沌工程平台，可在 Kubernetes 环境中编排混沌。
* [failure-lambda](https://github.com/gunnargrosch/failure-lambda) - 一个用于在 AWS Lambda 中通过延迟、异常、状态码或磁盘空间注入故障的小型 Node 模块。
* [aws-chaos-scripts](https://github.com/adhorn/aws-chaos-scripts) - 一组用于在 AWS 基础设施上执行故障注入的 Python 脚本。
* [chaos-ssm-documents](https://github.com/adhorn/chaos-ssm-documents) - 一组用于执行混沌工程实验的 AWS SSM 文档。
* [aws-lambda-chaos-injection](https://github.com/adhorn/aws-lambda-chaos-injection) - 一个向 AWS Lambda 注入混沌的库。它提供简单的 Python 装饰器来进行延迟、异常和状态码注入，并提供一个类用于为任何第三方依赖添加延迟。
* [chaos-dingo](https://github.com/jmspring/chaos-dingo) - 一款使用 Azure NodeJS SDK 来干扰 Azure 服务的工具。
* [Chaos HTTP Proxy](https://github.com/bouncestorage/chaos-http-proxy) - 通过代理服务器向 HTTP 请求中注入故障。
* [Chaos Lemur](https://github.com/strepsirrhini-army/chaos-lemur) - 一款可自行托管的应用，用于在 BOSH 管理的环境中随机销毁虚拟机。
* [Simoorg](https://github.com/linkedin/simoorg) - 领英自家的故障诱导框架。
