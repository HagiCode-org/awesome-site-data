## Обзор

**Генерация с дополненной выборкой (RAG)** — продвинутая технология генеративного ИИ, расширяющая возможности больших языковых моделей (LLM): во время генерации она динамически извлекает и учитывает релевантный контекст из внешних источников знаний. В отличие от традиционных LLM, опирающихся только на предобученные знания, системы RAG дают моделям доступ к актуальной, предметной или закрытой информации, значительно повышая точность, снижая число галлюцинаций и обеспечивая интеграцию знаний в реальном времени.

### Ключевые преимущества

- **Снижение числа галлюцинаций**: Формирует ответы на основе найденных фактических данных
- **Адаптация к предметной области**: Позволяет LLM работать со специализированными знаниями без дообучения
- **Обновления в реальном времени**: Учитывает актуальную информацию без переобучения модели
- **Экономическая эффективность**: Экономичнее дообучения для задач в конкретной предметной области
- **Прозрачность**: Указывает источники сгенерированного содержимого
- **Конфиденциальность и безопасность**: Хранит конфиденциальные данные в частных базах знаний

## ℹ️ Общие сведения о RAG

RAG устраняет фундаментальное ограничение LLM: фиксированную дату актуальности знаний и неспособность обращаться к внешней информации. В традиционных реализациях RAG конвейер поиска дополняет запросы к LLM контекстно-релевантными документами из базы знаний. Например, при вопросе о материалах для ремонта конкретного дома LLM может знать общие сведения о ремонте, но не детали этого объекта. Система RAG извлечёт нужные документы (планы, спецификации материалов, местные строительные нормы) и даст точный ответ с учётом контекста.

## 🏗️ Архитектурные шаблоны

Архитектуру систем RAG можно строить по различным шаблонам в зависимости от требований:

- **Naive RAG**: Базовый конвейер «поиск, затем генерация» без оптимизации
- **Advanced RAG**: Включает переформулирование запросов, переранжирование и сжатие контекста
- **Modular RAG**: Компоненты поиска, ранжирования и генерации можно комбинировать
- **Agentic RAG**: Агенты на основе LLM динамически принимают решения о поиске
- **Self-RAG**: Модели анализируют качество поиска и корректируют стратегии
- **Graph RAG**: Использует графы знаний для структурированного поиска информации
- **Reasoning-Based RAG**: Применяет многошаговые рассуждения LLM для планирования, навигации и выполнения поиска

## 🎯 Продвинутые подходы

Реализации RAG различаются по сложности: от простого поиска документов до продвинутых методов с итеративными циклами обратной связи, мультиагентными системами и отраслевыми улучшениями. Современные подходы включают:

- [Vision-RAG](https://www.youtube.com/watch?v=npkp4mSweEg): Встраивает целые страницы как изображения, позволяя моделям компьютерного зрения рассуждать напрямую без разбора текста, как в текстовом RAG.
- [Cache-Augmented Generation (CAG)](https://medium.com/@ronantech/cache-augmented-generation-cag-in-llms-a-step-by-step-tutorial-6ac35d415eec): Заранее загружает релевантные документы в контекст модели и сохраняет состояние инференса (KV-кэш).
- [Agentic RAG](https://langchain-ai.github.io/langgraph/tutorials/rag/langgraph_agentic_rag/): Также известны как агенты поиска и могут принимать решения о процессе поиска.
- [A-RAG](https://github.com/Ayanami0730/arag): Агентная RAG с иерархическими интерфейсами поиска (по ключевым словам, семантике и фрагментам), позволяющая агентам LLM самостоятельно искать и извлекать данные с разной детализацией. ([Paper](https://arxiv.org/abs/2602.03442))
- [Corrective RAG](https://arxiv.org/pdf/2401.15884.pdf) (CRAG): Методы исправления или уточнения извлечённой информации перед включением в ответы LLM.
- [Retrieval-Augmented Fine-Tuning](https://techcommunity.microsoft.com/t5/ai-ai-platform-blog/raft-a-new-way-to-teach-llms-to-be-better-at-rag/ba-p/4084674) (RAFT): Методы тонкой настройки LLM специально для улучшения поиска и генерации.
- [Self Reflective RAG](https://selfrag.github.io/): Модели, динамически адаптирующие стратегии поиска на основе обратной связи о производительности.
- [RAG Fusion](https://arxiv.org/abs/2402.03367): Методы объединения нескольких способов поиска для улучшения интеграции контекста.
- [Temporal Augmented Retrieval](https://adam-rida.medium.com/temporal-augmented-retrieval-tar-dynamic-rag-ad737506dfcc) (TAR): Учитывает временную актуальность данных при поиске.
- [Plan-then-RAG](https://arxiv.org/abs/2406.12430) (PlanRAG): Стратегии с этапом планирования перед запуском RAG для сложных задач.
- [GraphRAG](https://github.com/microsoft/graphrag): Структурированный подход с графами знаний для улучшения интеграции контекста и рассуждений.
- [Code-Graph-RAG](https://github.com/vitali87/code-graph-rag): Система RAG на графе знаний для анализа многоязычных кодовых баз.
- [FLARE](https://medium.com/etoai/better-rag-with-active-retrieval-augmented-generation-flare-3b66646e2a9f) - Подход с активной генерацией, дополненной поиском, для повышения качества ответов.
- [GNN-RAG](https://github.com/cmavro/GNN-RAG): Поиск с помощью графовых нейронных сетей для рассуждений больших языковых моделей.
- [Multimodal RAG](https://developer.nvidia.com/blog/an-easy-introduction-to-multimodal-retrieval-augmented-generation/): Расширяет RAG для работы с текстом, изображениями, аудио и другими модальностями.
- [VideoRAG](https://arxiv.org/abs/2501.05874): Расширяет RAG на видео с помощью больших видеоязыковых моделей (LVLM), извлекающих и объединяющих визуальное и текстовое содержимое для мультимодальной генерации.
- [REFRAG](https://arxiv.org/pdf/2509.01092): Оптимизирует декодирование RAG, сжимая извлечённый контекст в эмбеддинги перед генерацией, что снижает задержку без потери качества результата.
- [InstructRAG](https://github.com/weizhepei/InstructRAG): Повышает качество поиска и генерации в системах RAG за счёт дообучения на инструкциях с самостоятельно синтезированными рассуждениями.
- [PageIndex](https://github.com/VectifyAI/PageIndex): Безвекторный фреймворк на основе рассуждений: строит иерархические деревья документов и выполняет поиск по дереву под управлением LLM, а не по эмбеддингам и векторному сходству. Устраняет необходимость в разбиении на фрагменты и векторных БД, обеспечивая объяснимый контекстный поиск по сложным профессиональным документам.

### Разбиение на фрагменты

Стратегия разбиения на фрагменты — одно из важнейших решений при проектировании систем RAG, напрямую влияющее на точность поиска и качество контекста. Оптимальный подход зависит от типов документов, особенностей предметной области и шаблонов запросов.

- **[Fixed-Size Chunking](https://medium.com/@anuragmishra_27746/five-levels-of-chunking-strategies-in-rag-notes-from-gregs-video-7b735895694d)**
  - **Применение**: Простые однородные документы, в которых структура не так важна
  - **Характеристики**: Делит текст на сегменты одинакового размера (обычно 256–512 токенов) с настраиваемым перекрытием (10–20%)
  - **Преимущества**: Простая реализация, предсказуемый размер фрагментов, эффективная обработка
  - **Недостатки**: Может разрезать предложения и абзацы, теряет структуру документа и фрагментирует смысловые единицы
  - **Реализация**: [CharacterTextSplitter](https://python.langchain.com/v0.1/docs/modules/data_connection/document_transformers/character_text_splitter/) (LangChain), [SentenceSplitter](https://docs.llamaindex.ai/en/stable/api_reference/node_parsers/sentence_splitter/) (LlamaIndex)

- **[Recursive Chunking](https://medium.com/@AbhiramiVS/chunking-methods-all-to-know-about-it-65c10aa7b24e)**
  - **Применение**: Документы с иерархической структурой (Markdown, HTML, код)
  - **Характеристики**: Рекурсивно делит текст по разделителям (абзацы → предложения → слова), пока не будет достигнут нужный размер фрагмента
  - **Преимущества**: Сохраняет естественные границы и иерархию документа, улучшает смысловую связность
  - **Недостатки**: Сложнее в реализации; размер фрагментов меняется; требуется тщательно настраивать разделители
  - **Реализация**: [RecursiveCharacterTextSplitter](https://python.langchain.com/v0.1/docs/modules/data_connection/document_transformers/recursive_text_splitter/) (LangChain)

- **[Document-Based Chunking](https://medium.com/@david.richards.tech/document-chunking-for-rag-ai-applications-04363d48fbf7)**
  - **Применение**: Структурированные документы с чёткими разделами (заголовки Markdown, разделы PDF, записи баз данных)
  - **Характеристики**: Разбивает данные с учётом метаданных документа, форматирования или структурных элементов
  - **Преимущества**: Сохраняет структуру и контекст документа, позволяет искать с использованием подробных метаданных
  - **Недостатки**: Требует структурированного ввода; фрагменты могут оказаться слишком большими или маленькими
  - **Реализация**: [MarkdownHeaderTextSplitter](https://python.langchain.com/v0.1/docs/modules/data_connection/document_transformers/markdown_header_metadata/) (LangChain)
  - **Мультимодальность**: Обработка изображений и текста с помощью таких моделей, как [OpenCLIP](https://github.com/mlfoundations/open_clip)

- **[Semantic Chunking](https://www.youtube.com/watch?v=8OJC21T2SL4&t=1933s)**
  - **Применение**: Документы, где критически важна смысловая связность (повествовательные тексты, техническая документация)
  - **Характеристики**: Использует сходство векторных представлений для определения естественных смысловых границ
  - **Преимущества**: Сохраняет смысловые единицы, адаптируется к содержимому и повышает релевантность поиска
  - **Недостатки**: Требует значительных вычислительных ресурсов и модели векторных представлений; размер фрагментов менее предсказуем
  - **Лучше всего подходит для**: Поиск высокого качества, в котором сохранение контекста особенно важно

- **[Agentic Chunking](https://youtu.be/8OJC21T2SL4?si=8VnYaGUaBmtZhCsg&t=2882)**
  - **Применение**: Сложные документы, требующие интеллектуального определения границ сегментов
  - **Характеристики**: Использует LLM для анализа содержимого и определения оптимальных границ фрагментов
  - **Преимущества**: Высокая адаптивность, понимание контекста и применение знаний предметной области
  - **Недостатки**: Высокая стоимость и медленная обработка; требуется доступ к API LLM
  - **Лучше всего подходит для**: Специализированные предметные области, где стандартные методы разбиения не подходят

- **[Adaptive Chunking](https://github.com/ekimetrics/adaptive-chunking)**
  - **Применение**: Смешанные коллекции документов, для которых нужны разные стратегии разбиения
  - **Характеристики**: Оценивает несколько методов разбиения по внутренним метрикам и выбирает лучший для каждого документа
  - **Преимущества**: Гибче универсального подхода, сохраняет структуру и смысловую связность, поддерживает пользовательские разделители и метрики
  - **Недостатки**: По сравнению с разбиением на фрагменты фиксированного размера или рекурсивным добавляет затраты на оценку и усложняет реализацию

**Практические рекомендации по разбиению на фрагменты:**
- **Стратегия перекрытия**: Перекрытие 10–20% помогает сохранять контекст на границах фрагментов
- **Оптимизация размера**: Подбирайте баланс размера фрагмента: больший даёт больше контекста, меньший повышает точность
- **Сохранение метаданных**: Сохраняйте структуру документа, заголовки и форматирование в метаданных фрагментов
- **Разная гранулярность**: Используйте иерархический подход: небольшие фрагменты для поиска, более крупные — для контекста

### Векторные представления

Векторные представления лежат в основе семантического поиска в системах RAG. Выбор модели векторных представлений существенно влияет на качество поиска.

- **Выбор модели**
  - **[MTEB Leaderboard](https://huggingface.co/spaces/mteb/leaderboard)**: Обширный набор тестов для оценки моделей векторных представлений по различным задачам и языкам. Выбирайте модели, хорошо справляющиеся с задачами вашего сценария (поиск, кластеризация, классификация).
  - **Характеристики моделей**: Оценивайте модели по следующим параметрам:
    - **Размерность**: Большая размерность (768–1024) обычно повышает качество, но увеличивает затраты на хранение и вычисления
    - **Длина контекста**: Убедитесь, что модели поддерживают размеры фрагментов ваших документов
    - **Поддержка нескольких языков**: Необходима для международных приложений
    - **Специализация на предметной области**: Универсальные или специализированные модели (например, для научной, юридической или медицинской сферы)
  
- **Пользовательские векторные представления**
  - **Дообучение**: Адаптируйте предварительно обученные модели к своей предметной области с помощью контрастивного обучения, triplet loss или контролируемого дообучения
  - **Обучение с нуля**: Подходит для узкоспециализированных областей при наличии достаточного объёма размеченных данных
  - **Мультимодальные векторные представления**: Для приложений, которым нужно понимать текст, изображения или аудио (например, CLIP, ImageBind)
  - **Ансамблевые методы**: Объединяйте несколько моделей векторных представлений для повышения устойчивости

### Поиск

- **Методы поиска**
  - [Vector Store Flat Index](https://weaviate.io/developers/academy/py/vector_index/flat)
    - Простой и эффективный способ поиска.
    - Содержимое преобразуется в векторы и сохраняется в виде плоского набора векторов.
  - [Hierarchical Index Retrieval](https://pixion.co/blog/rag-strategies-hierarchical-index-retrieval)
    - Последовательно сужает область поиска по уровням иерархии.
    - Выполняет поиск, последовательно проходя уровни иерархии.
  - [Hypothetical Questions](https://pixion.co/blog/rag-strategies-hypothetical-questions-hyde)
    - Повышает сходство между фрагментами в базе данных и запросами (так же, как HyDE).
    - LLM генерирует конкретные вопросы для каждого текстового фрагмента.
    - Преобразует эти вопросы в векторные представления.
    - При поиске запросы сопоставляются с этим индексом векторов вопросов.
  - [Hypothetical Document Embeddings (HyDE)](https://pixion.co/blog/rag-strategies-hypothetical-questions-hyde)
    - Повышает сходство между фрагментами в базе данных и запросами (так же, как метод гипотетических вопросов).
    - LLM генерирует гипотетический ответ на основе запроса.
    - Преобразует этот ответ в векторное представление.
    - Сравнивает вектор запроса с вектором гипотетического ответа.
  - [Small to Big Retrieval](https://github.com/GoogleCloudPlatform/generative-ai/blob/main/gemini/use-cases/retrieval-augmented-generation/small_to_big_rag/small_to_big_rag.ipynb)
    - Повышает качество поиска: для поиска используются более мелкие фрагменты, а для контекста — более крупные.
    - Мелкие дочерние фрагменты ссылаются на более крупные родительские.
  - [Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)
    - Повышает точность поиска в RAG, сохраняя контекст документа, который обычно теряется при разбиении на фрагменты.
    - Перед созданием векторных представлений и индексированием каждый текстовый фрагмент дополняется кратким сгенерированным моделью резюме, что позволяет получить контекстные векторные представления и контекстный BM25.
    - Такой комбинированный подход улучшает семантическое и лексическое сопоставление, а при использовании переранжирования снижает вероятность неудачного поиска.
  - [Adaptive Retrieval](https://arxiv.org/abs/2403.14403)
    - Динамически определяет, когда и какой объём данных извлекать во время генерации.
  - [Query Reformulation and Expansion](https://haystack.deepset.ai/cookbook/query-expansion)
    - Автоматически переформулирует или расширяет запрос перед поиском, чтобы повысить полноту результатов.
    - Полезно для длинных или неоднозначных пользовательских запросов.
- **[Re-ranking](https://developer.nvidia.com/blog/enhancing-rag-pipelines-with-re-ranking/)**: Улучшает результаты поиска в конвейерах RAG, переупорядочивая изначально найденные документы и ставя выше те, которые семантически лучше всего соответствуют запросу.

### Модели оценки и принятия решений

Модели суждений принимают ограниченные семантические решения на основе извлечённого содержимого, запросов, сгенерированных ответов или состояния конвейера. В отличие от генеративных LLM, их можно использовать как программируемые точки принятия решений в конвейерах RAG для переранжирования, фильтрации, маршрутизации, проверки и оценки.

- **[Jev](https://typesafe.ai/)**: Модель System One от TypeSafe AI для быстрых типизированных решений. В RAG она может выполнять переранжирование, фильтрацию, маршрутизацию, проверку, обеспечивать защитные механизмы и оценку.
- **[AnyJev](https://github.com/nokia-applied-research/AnyJev)**: Преобразует открытые LLM в типизированные модели принятия решений в стиле Jev; включает коррекцию смещения без меток и необязательную калибровку для решений с пороговыми значениями.

### Качество и безопасность ответов

Для систем RAG, используемых в промышленной среде, крайне важно обеспечивать высокое качество, безопасность и надёжность ответов.

- **Снижение числа галлюцинаций**
  - **[Detection Techniques](https://machinelearningmastery.com/rag-hallucination-detection-techniques/)**: Реализуйте методы для выявления случаев, когда модели генерируют неподтверждённую информацию
  - **Проверка опоры на контекст**: Сопоставляйте сгенерированные утверждения с извлечённым контекстом
  - **Оценка уверенности**: Оценивайте уверенность в сгенерированных ответах по качеству источников
  - **Указание источников**: Требуйте указывать источники для всех фактических утверждений
  - **Качество поиска**: Повышайте точность поиска, чтобы снизить риск галлюцинаций

- **Защитные механизмы и безопасность**
  - **[Implementation Guide](https://developer.ibm.com/tutorials/awb-how-to-implement-llm-guardrails-for-rag-applications/)**: Комплексный подход к внедрению механизмов безопасности
  - **Модерация содержимого**: Фильтруйте вредоносное, предвзятое или недопустимое содержимое на этапах ввода и вывода
  - **Снижение предвзятости**: Выявляйте и снижайте предвзятость в извлечённом содержимом и сгенерированных ответах
  - **Проверка фактов**: Проверяйте утверждения по авторитетным источникам или базам знаний
  - **Обнаружение токсичности**: Используйте классификаторы для выявления и фильтрации токсичного содержимого

- **Предотвращение внедрения промптов**
  - **[Security Guide](https://hiddenlayer.com/innovation-hub/prompt-injection-attacks-on-llms/)**: Изучение и предотвращение атак с внедрением промптов
  - **Проверка входных данных**: Тщательно проверяйте и очищайте все внешние входные данные с помощью белых списков, ограничений длины и сопоставления с шаблонами
  - **Разделение содержимого**: Используйте чёткие разделители, шаблоны и промпты с заданными ролями, чтобы отделять инструкции от пользовательских данных
  - **Мониторинг результатов**: Постоянно отслеживайте аномалии, неожиданное поведение и нарушения безопасности в ответах
  - **Ограничение частоты запросов**: Настройте ограничения частоты запросов и обнаружение злоупотреблений для предотвращения систематических атак
  - **Изоляция в песочнице**: Изолируйте среды выполнения LLM, чтобы ограничить возможный ущерб от успешных атак с внедрением промптов

## 📊 Метрики и оценка

### Метрики сходства векторных представлений

Эти метрики позволяют измерять сходство между векторными представлениями, что важно для оценки эффективности поиска и интеграции внешних документов и источников данных системами RAG. Выбор подходящих метрик сходства помогает оптимизировать производительность и точность системы RAG. Также можно разработать специальные метрики для конкретной предметной области, чтобы учитывать её особенности и повышать релевантность.

- **[Cosine Similarity](https://en.wikipedia.org/wiki/Cosine_similarity)**

  - Измеряет косинус угла между двумя векторами в многомерном пространстве.
  - Эффективна для сравнения векторных представлений текста, направление которых несёт семантическую информацию.
  - Часто используется в системах RAG для измерения семантического сходства между векторами запросов и документов.

- **[Dot Product](https://en.wikipedia.org/wiki/Dot_product)**

  - Вычисляет сумму произведений соответствующих элементов двух числовых последовательностей.
  - Эквивалентно косинусному сходству, если векторы нормализованы.
  - Просто и эффективно; часто используется с аппаратным ускорением для крупномасштабных вычислений.

- **[Euclidean Distance](https://en.wikipedia.org/wiki/Euclidean_distance)**

  - Вычисляет расстояние по прямой между двумя точками в евклидовом пространстве.
  - Можно применять к векторным представлениям, однако в пространствах большой размерности эффективность может снижаться из-за «[проклятия размерности](https://stats.stackexchange.com/questions/99171/why-is-euclidean-distance-not-a-good-metric-in-high-dimensions)».
  - Часто используется в алгоритмах кластеризации, например K-means, после снижения размерности.

- **[Jaccard Similarity](https://en.wikipedia.org/wiki/Jaccard_index)**
  - Измеряет сходство двух конечных множеств как отношение размера пересечения к размеру объединения.
  - Полезно при сравнении наборов токенов, например в моделях «мешка слов» или при сравнении n-грамм.
  - Менее применимо к непрерывным векторным представлениям, создаваемым LLM.

> **Примечание:** Косинусное сходство и скалярное произведение обычно считают наиболее эффективными метриками для измерения сходства векторных представлений большой размерности.

### Метрики оценки ответов

Оценка ответов в решениях RAG включает измерение качества результатов языковой модели с помощью различных метрик. Ниже приведены структурированные подходы к такой оценке:

- **Автоматизированное тестирование**

  - **[BLEU](https://en.wikipedia.org/wiki/BLEU):** Оценивает совпадение n-грамм машинного и эталонного текстов, помогая оценить точность.
  - **[ROUGE](<https://en.wikipedia.org/wiki/ROUGE_(metric)>):** Измеряет полноту, сопоставляя с эталонными ответами n-граммы, пропускающие биграммы или наибольшую общую подпоследовательность.
  - **[METEOR](https://en.wikipedia.org/wiki/METEOR):** Оценивает машинный перевод по точным совпадениям, стеммингу, синонимам и выравниванию.

- **Оценка человеком**
  При оценке люди проверяют ответы на следующие свойства:
  - Соответствие пользовательским запросам.
  - Грамматическое и стилистическое качество.
  - Проверка утверждений по авторитетным источникам.
  - Логическая согласованность ответа.
  
  Подходы включают:
  - **[Annotation queues](https://docs.langchain.com/langsmith/annotation-queues):** Предоставляют разметчикам удобное представление с заданным направлением, позволяющее оставлять отзывы о конкретных запусках.

- **Оценка моделей**
  Используются предварительно обученные оценщики для сравнения результатов по различным критериям:

  - **[TuringBench](https://turingbench.ist.psu.edu/):** Обеспечивает всестороннюю оценку по языковым тестам.
  - **[Hugging Face Evaluate](https://huggingface.co/docs/evaluate/en/index):** Оценивает соответствие предпочтениям людей.

- **Ключевые аспекты оценки**
  - Показывает, полностью ли ответы основаны на предоставленном контексте. Низкий уровень опоры на контекст может говорить о том, что ответ содержит галлюцинации или нерелевантную информацию.
  - Показывает, охватывает ли ответ все аспекты запроса.
  - Оценка поиска с помощью ИИ и проверка намерений на основе промптов.
  - Показывает, в какой степени извлечённые данные повлияли на ответ.
  - Используйте LLM, чтобы проверить, включены ли найденные фрагменты в ответы.

## 🚀 Особенности промышленной эксплуатации

Для создания готовых к промышленной эксплуатации систем RAG необходимо учитывать несколько важных аспектов, выходящих за рамки основного конвейера поиска и генерации:

### Масштабируемость и производительность

- **Пропускная способность индексирования**: Проектируйте конвейеры для обработки больших объёмов поступающих документов и инкрементальных обновлений
- **Задержка запросов**: Ускоряйте поиск за счёт эффективного индексирования (HNSW, IVF), кэширования и параллельной обработки
- **Параллельные запросы**: Для высокой нагрузки используйте пулы подключений, очереди запросов и балансировку нагрузки
- **Управление ресурсами**: Отслеживайте загрузку GPU/CPU, потребление памяти и пулы подключений к базам данных

### Надёжность и мониторинг

- **Наблюдаемость**: Настройте комплексный сбор журналов, трассировок и метрик (задержка, пропускная способность, число ошибок)
- **Проверки работоспособности**: Отслеживайте доступность службы векторных представлений, подключение к векторной базе данных и состояние API LLM
- **Обработка ошибок**: Используйте повторы запросов, автоматические выключатели и стратегии плавного снижения функциональности
- **A/B-тестирование**: Сравнивайте различные стратегии поиска, методы разбиения на фрагменты и шаблоны промптов

### Управление данными

- **Инкрементальные обновления**: Поддерживайте индексирование документов в реальном или почти реальном времени без полного переиндексирования
- **Контроль версий**: Отслеживайте версии документов, моделей векторных представлений и шаблонов промптов
- **Качество данных**: Настройте конвейеры проверки для выявления повреждённых векторных представлений, отсутствующих метаданных и устаревшего содержимого
- **Резервное копирование и восстановление**: Регулярно создавайте резервные копии векторных индексов и хранилищ метаданных

### Безопасность и соответствие требованиям

- **Контроль доступа**: Реализуйте аутентификацию, авторизацию и ведение журнала аудита
- **Конфиденциальность данных**: Шифруйте данные при хранении и передаче; соблюдайте требования к месту хранения данных
- **Фильтрация содержимого**: Применяйте модерацию содержимого, обнаружение персональных данных и проверки соответствия требованиям
- **Ограничение частоты запросов**: Защищайтесь от злоупотреблений и обеспечивайте справедливое распределение ресурсов

### Оптимизация затрат

- **Кэширование векторных представлений**: Кэшируйте часто используемые векторные представления для снижения расходов на API
- **Избирательный поиск**: Используйте маршрутизацию запросов, чтобы избежать ненужных операций поиска
- **Выбор модели**: При выборе моделей векторных представлений и LLM учитывайте баланс затрат и производительности
- **Оптимизация ресурсов**: Оптимизируйте инфраструктуру с учётом фактических моделей использования

## 💡 Лучшие практики

### Стратегия разбиения на фрагменты

- **Разбиение с учётом предметной области**: Для лучшего сохранения контекста используйте семантическое разбиение или разбиение по структуре документа вместо фрагментов фиксированного размера
- **Управление перекрытием**: Стратегически применяйте перекрытие (10–20%), чтобы сохранять контекст на границах фрагментов
- **Сохранение метаданных**: Сохраняйте структуру документа, заголовки и подсказки форматирования в метаданных фрагментов
- **Разная гранулярность**: Рассмотрите иерархическое разбиение: небольшие фрагменты для поиска и более крупные для контекста

### Выбор векторных представлений

- **Оценка моделей**: Используйте таблицу лидеров MTEB и тесты для конкретной предметной области, чтобы выбрать подходящие модели
- **Оптимизация размерности**: Подбирайте баланс размерности векторных представлений: большая повышает качество, меньшая ускоряет поиск
- **Дообучение для предметной области**: При возможности дообучайте векторные представления на данных конкретной предметной области
- **Согласованность**: Используйте одну и ту же модель векторных представлений при индексировании и поиске

### Оптимизация поиска

- **Гибридный поиск**: Сочетайте семантический (векторный) и лексический поиск (BM25/по ключевым словам) для повышения полноты результатов
- **Переранжирование**: Используйте кросс-энкодеры или модели ранжирования для повышения точности
- **Понимание запросов**: Реализуйте классификацию запросов, определение намерений и расширение запросов
- **Разнообразие результатов**: Избегайте дублирующихся результатов с помощью ограничений на разнообразие

### Разработка промптов

- **Чёткие инструкции**: Чётко указывайте, как использовать извлечённый контекст
- **Указание источников**: Запрашивайте цитаты и требуйте, чтобы ответы основывались на предоставленном контексте
- **Примеры для Few-Shot**: Добавляйте примеры желаемого формата и качества ответов
- **Сжатие контекста**: Если контекст превышает ограничения, используйте суммаризацию или извлечение нужных сведений

### Система оценки

- **Многомерные метрики**: Оценивайте релевантность, точность, полноту и опору на источники
- **Участие человека в цикле**: Используйте отзывы людей для непрерывного улучшения
- **Синтетическая оценка**: Создавайте тестовые запросы и ожидаемые результаты для автоматизированного тестирования
- **Мониторинг в промышленной среде**: Отслеживайте удовлетворённость пользователей, шаблоны запросов и типы сбоев

### Итеративное улучшение

- **Циклы обратной связи**: Собирайте отзывы пользователей, журналы запросов и метрики производительности
- **Эксперименты**: Систематически тестируйте улучшения (разбиение на фрагменты, поиск, промпты) в контролируемых экспериментах
- **Обновления моделей**: Планируйте обновление моделей векторных представлений и стратегии миграции
- **Документация**: Ведите понятную документацию по архитектуре, принятым решениям и рабочим процедурам
